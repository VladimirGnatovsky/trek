# Trek — аудит продукта и план развития

## Что уже хорошо

- Очень быстрый офлайн-сценарий: расход можно сохранить без аккаунта и сети.
- Уместный для iPhone формат: крупная сумма, нижняя навигация, быстрый ввод и чек.
- Локальные данные дают понятную приватность для первой версии.

## Что изменено в этой версии

1. **Доходы и доступные деньги.** Расходы без дохода показывают только прошлое. Теперь можно добавить доход и сразу видеть «доступно в этом месяце».
2. **Регулярные платежи.** При добавлении расхода его можно пометить как ежемесячный; список плановых платежей доступен в статистике.
3. **Резервная копия.** Добавлены экспорт и проверяемый импорт JSON. Это первый обязательный шаг перед синхронизацией и сменой устройства.
4. **Безопаснее сканирование.** Убран интерфейс, который предлагает хранить ключ провайдера ИИ в браузере. Для распознавания нужен собственный HTTPS-proxy; ключ остаётся на сервере.
5. **Компьютерный режим.** На ширине от 760px приложение становится рабочим столом: боковая навигация, две колонки, больше воздуха и большая панель результата. Это та же база данных браузера, поэтому для реальной синхронизации нужен аккаунт и сервер.

## Что показывают сильные аналоги

- YNAB делает акцент на целях, назначении денег и отчётах; у него есть цели и планировщик долга.
- Monarch объединяет счета, активы/обязательства, поиск операций и совместный доступ.
- Copilot фокусируется на удобном обзоре: расход за месяц, повторяющиеся платежи, категории и подсказки.

Для Trek разумнее не копировать весь банковский агрегатор на первом этапе. Его сильная позиция — **приватный и быстрый ручной учёт для Украины/Польши с понятным прогнозом «сколько можно потратить»**.

## Приоритеты следующего релиза

### P0 — до App Store / публичного запуска

- Настоящее облако: учётная запись, шифрование на сервере, синхронизация iPhone и веба.
- Политика конфиденциальности, удаление аккаунта и экспорт данных; это критично, если появится вход или аналитика.
- Серверный ИИ-proxy с rate limit, авторизацией и журналом ошибок без содержимого чеков.
- Ручное редактирование и undo удаления операции; подтверждение удаления вместо мгновенной кнопки X.

### P1 — ценность продукта

- Цели накоплений с ежемесячным взносом и прогрессом.
- Бюджеты по категориям и предупреждение до, а не после превышения.
- Календарь ближайших регулярных расходов и расчёт «безопасно потратить».
- CSV/XLSX import/export, теги, поиск по сумме и периоду.
- Локализация: украинский, русский, польский, английский; формат дат и чисел по локали.

### P2 — только после спроса

- Подключение банков через лицензированного Open Banking-провайдера.
- Семейный доступ с ролями и раздельными/общими кошельками.
- Премиум: синхронизация, неограниченные цели, семейный доступ, расширенный экспорт. Покупки в iOS должны оформляться через StoreKit/In-App Purchase; не картой внутри приложения.

## Платежи и карта

Номер банковской карты не должен появляться ни в исходниках, ни в формах, ни в клиентском JavaScript. Для подписки в iOS обязателен In-App Purchase. Для веб-подписки нужен договор с платёжным провайдером (например Stripe/WayForPay/LiqPay — в зависимости от страны юрлица), его hosted checkout и серверные webhooks. В таком сценарии приложение хранит только технический ID клиента/подписки, а не номер карты, CVV или срок действия.

## Технический долг из архива

- Один файл `src/ledger.jsx` стоит разделить на `features/transactions`, `features/reports`, `features/settings` и общие компоненты.
- Чеки в localStorage быстро упрутся в лимит. Для офлайн-чеков нужен IndexedDB, для облака — шифрованное object storage.
- Даты лучше обрабатывать через timezone-safe библиотеку или Temporal после её широкого появления в целевых WebView.
- Нужны unit-тесты для парсера, миграций backup и расчёта итогов; затем e2e для добавления/удаления/импорта.
